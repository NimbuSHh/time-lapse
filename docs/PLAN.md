# Time-lapse 开发方案

2026-10-11 · 首版 0.1

本文是首版开发时的历史方案。当前功能、安装方式和使用边界以 [README](../README.md) 为准。

## 背景与目标

首版围绕 810 帧日出 RAW 序列开发，希望消除调节曝光造成的台阶与短时闪烁，保留日出渐亮和既有调色。
初始流程为：ACR 保存同名 XMP → 导出小尺寸 JPEG → 工具分析并产生逐帧曝光调整 → ACR 重显影验证 → ACR 导出最终图像 → 外部工具合成视频。
本项目关注可检查的序列曲线、逐事件控制和安全补偿闭环。

## 第一性原理

1. 显影后亮度 = 场景光线、相机曝光、ACR 非线性显影的共同结果；单一 JPEG 亮度无法唯一反推出其中任何一个因素。
2. 相机参数变化是断点证据，不是修正值。只补偿用户确认的、图像中实际观察到的跳变量；不重复叠加 EXIF 或已有 XMP 的补偿。
3. 短时平滑与持续台阶分开。固定 ROI / 共同空间区域测量避免测光区域随帧变化；局部线性最小二乘趋势尽量保留日出变化。
4. 线性化 sRGB 的 EV 差只是 ACR Exposure2012 的近似增量。最终质量只能由 ACR 重显影后复核，不能通过预览模拟证明。
5. 原 RAW 始终只读；XMP 在分析与仅导出时只读。用户选择自动应用时，先完成可恢复备份，再原子替换各 XMP。生成可审查的新 XMP 包，附原始字节备份、来源哈希、参数和固定目标曲线。

## 首版交付

Python + NumPy/Pillow，本地 loopback Web 工作台，无云端处理。单序列、同名 RAW/XMP/JPEG 严格映射、自然文件名排序并确认、固定 ROI、手动调参候选、逐事件选择、短时平滑、首尾创作偏移、逐帧表/曲线/预览播放、新目录安全导出、重显影数值复核。JPEG 必须由本轮对应 XMP 显影成 sRGB；这项来源无法自动证明，导入时需声明。
仅现代 ACR、独立 XMP，现有 Exposure2012 单一数值。首版不处理 DNG 内嵌设置、自动 RAW 显影、ACR UI 自动化、局部调色、视频渲染或云服务。

## 算法契约

固定 8×8 tiles，所有帧共同有效的 tile 至少 8 个。统计 log2(线性亮度)，记录高光/暗部比例。
相机参数 log2(t×ISO/N²) 的变化定位候选。回归窗口不得跨其他事件或时间缺口。每侧不足 3 帧、测量支持不足时禁止建议。所有事件初始不选。
未确认参数候选、已有曝光编辑边界和时间缺口均分段平滑；已确认并去除的纯相机台阶允许跨边界平滑。
2026-10-12 修订：先计算去台阶与短时平滑补偿，再减去该补偿的首尾线性插值，最后加上用户首尾偏移插值。默认首尾增量均为0，保留原始显影首尾亮度；不把日出期间的多次调暗无限累加补回。这是成片亮度策略，不声称还原物理光照。超 ±2 EV 增量或最终 Exposure2012 超 ±5 EV 时阻止导出，不静默裁剪。
短平台不足3帧的连续调参按组联合估计，最多跨13帧，前后各至少5个稳定样本；拒绝跨缺口、已有曝光编辑、平台拍摄参数不稳定或空间证据不一致。组内每个平台从图像实际测量得到，只由稳定前后窗口估计自然亮度斜率；响应增益由稳定净变化或独立单事件校准。确认与撤销按组进行。
重显影复核沿用原 ROI 和 tile 支持，比较冻结目标误差、端点趋势、已选事件剩余台阶及裁切比例；连续组同时报告每次剩余跳变及组内最大值，不能用净和掩盖中间凹口；不输出虚构成功评分。

## 审查与验收

开发前进行两轮算法与数据安全独立对抗性审查。开发后审实际实现和失败模式。
必测：已知日出趋势/曝光台阶/闪烁恢复；已补偿参数不再重复修正；自然突变不自动修复；密集事件降级；输入对应和顺序；XMP 属性/子节点/namespace/注释与歧义；源变更阻止导出；仅曝光数字变更；原文件哈希不变；异常输入与 HTTP 边界；810帧合成闭环和浏览器操作。
真实 810 张素材尚未提供，因此软件可运行和合成验收完成不等于用户素材/ACR 实际效果通过。
