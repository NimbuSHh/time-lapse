## 第一轮：攻击方案假设

由算法和文件安全两个独立审查角色分别检查。

| 问题 | 修订 |
| --- | --- |
| 把相机参数变化当作真因，会误消除云层和自然光变化 | 参数仅定位；所有阶跃初始不选，展示图像/参数/已有XMP三组证据 |
| EXIF、原XMP、图像跳变重复叠加会双重补偿 | 仅累计已确认的图像跳变量；原XMP只作为最终曝光基线 |
| 回归跨密集调参、缺口可能把其他事件混进来 | 回归不跨边界，单侧不足3帧拒绝估计 |
| 每帧单独剔除像素会造成测光区域漂移 | 固定空间tile，全序列共同支持至少8/64，保守失败 |
| 曲线变平滑无法证明日出真实变化被保留 | 复核冻结目标误差、首尾趋势、剩余事件与裁切比例 |
| 导出重读文件可能混用新旧XMP | 生成与备份都使用分析时保存的原字节；导出前核对哈希 |
| XML整体重写可能破坏其他调色设置 | namespace-aware精确定位数字跨度，其他字节保持 |
| 只限制压缩文件大小仍可能内存爆炸 | 限2400万解码像素、25MB JPEG、4MB单XMP、64MB总XMP；逐帧处理 |

## 第二轮：攻击修订方案

发现并修复：如果平滑窗口跨未确认台阶，仍会暗中改变它。最终在全部参数候选、已有曝光编辑边界和时间缺口处分段平滑。

确认仅导出新包，不增加原地 apply/restore。曝光目标只是待实测的近似；共同区域不足明确报错。快照校验只能证明校验时输入一致，不能锁定之后的 ACR 操作。

上述补齐后，两位审查者均未发现剩余设计阻塞，进入开发。

## 2026-10-12 自动备份、写回、恢复专项审查（修订后）

本次审查覆盖从 HTTP 会话/修订确认、原始快照校验、完整备份、逐帧替换、提交状态，到跨进程恢复和 UI 禁用状态的整条链路。仅使用隔离的合成素材。以下结论取代上一节中单文件直接替换的实现说明。

### 发现、复现与修复

1. **P1：校验与直接覆盖之间会丢失 ACR 并发编辑。** 原实现先读哈希，再 `os.replace`；在二者之间插入一次 ACR 式保存，可以复现新编辑既不在原始备份里，也不在替换后的文件里。修订后通过原子交换保留换出的实际 inode；每次交换前写入持久 receipt，换出的版本永久留在 `retained/`，不再 unlink。应用和恢复两个方向都有竞争窗口注入测试。ACR 持有旧文件描述符并延迟保存的情况也验证了版本被保留。发现不符合已知原始/修正哈希的版本时停止自动恢复并指出路径，交由人工核对，不静默选择创作设置。
2. **P2：自动应用依赖项目目录导出包。** 原备份确实在导入 RAW 目录内，但写回前会额外向项目 `outputs` 写修正包，造成位置混淆和不必要依赖。现自动应用仅写入导入 RAW/XMP 目录的 `Time-lapse-XMP备份/时间戳-编号/`，冻结复核目标另存为同一备份目录内的 `verification.json`。保留独立的“仅导出”功能，页面折叠展示该功能的项目输出位置。测试将项目根设置为普通文件，自动写回仍成功且项目内容未变。
3. **P2：只按时间戳排序不可靠。** 调低系统时钟时，最新写回可能被错误识别为旧版本。增加持久递增 sequence，始终按实际写回顺序撤销；以时钟回退一天的反例验证。已有 schema 1 备份仍可恢复。
4. **重复操作防护补强。** 除 HTTP 作业单飞、目录锁及会话 `written` 状态外，持久记录分析 snapshot_id；同一快照即便已恢复，也不能再次直接应用，必须重新分析。失败未提交的操作优先进入恢复，不能继续叠加写回。多次独立分析创建新的备份版本，不覆盖最早的 originals。
5. **其他修正。** 校验待写入的 corrected 字节，防止准备后被改动；拒绝损坏清单；目录描述符及目录身份校验避免目录在最后时刻被替换后把修正写到其他目录。旧版 backups 兼容保留。

### 故障边界与检查

| 场景 | 已验证行为 |
| --- | --- |
| 备份写入失败/无空间 | 源 XMP 不变，准备目录清理，可重新分析后重试 |
| 写回或恢复中途抛错 | 留下持久 applying/restoring 状态、完整 originals 和换出版本，恢复可继续 |
| 交换成功后报错、最终状态提交失败 | 原文件版本仍保留；再次恢复可完成，不依赖 Python finally 回滚 |
| 子进程第 3 次交换后 `os._exit(73)` | 实际进程终止后重新加载备份；写回和恢复两种中断均可继续恢复 |
| ACR 在分析后、恢复前改变 XMP | 全批前置校验拒绝覆盖 |
| ACR 在最后一瞬间原地写入或 rename 保存 | 新版本保留在 retained；最初设置仍在 originals，停止并报告冲突 |
| 打开的 ACR 文件描述符在交换后继续写 | 修改保留在换出的 inode，后续恢复检查会阻止静默丢弃 |
| 重复调用、多个版本、时钟回退 | 重复快照被拦截；新版本按持久顺序从新到旧恢复 |
| 备份损坏、符号链接、路径穿越、目录替换 | 拒绝继续；不把不可信字节写回 |
| 文件系统不支持原子交换 | 明确失败，不降级为直接覆盖；未交换的原文件不变 |

原子交换依据本机 SDK `sys/stdio.h` 以及 [Apple rename 手册](https://github.com/apple-oss-distributions/xnu/blob/main/bsd/man/man2/rename.2)；macOS 使用 `RENAME_SWAP` 并拒绝符号链接解析。每个原始备份和操作记录在源文件变更前同步，交换后同步两个目录和换出的文件。

### 验证结果与限度

- 完整 unittest：**75 个测试方法通过**；其中备份/恢复专项 **25 个方法**（原有 11 + 新增 14）。故障阶段、双方向交换、真实子进程退出由相应方法内部执行，不另算测试方法数。JS 语法、Python 编译检查通过。
- 浏览器从独立于服务根目录的 30 帧合成素材执行分析、自动应用和恢复。全部 61 个原文件（30 RAW、30 XMP、合成标识）恢复后哈希与操作前完全一致；备份全部位于导入 RAW 的子文件夹；服务项目根保持为空，未创建 outputs。截图 `xmp-safety-review.png`。
- 整批仍不是跨文件原子事务；失败可能留下部分修正，必须按持久状态恢复。发现并发创作编辑时保留所有捕获版本并暂停自动恢复，不能自动判定应该采用哪个版本。
- 此验证包含本机文件系统和进程故障注入，不等于实测物理断电、NAS 故障、磁盘损坏或 Adobe ACR 实际显影。需要关闭 ACR 中的此序列；同盘备份不能防范整块磁盘损坏。未修改用户真实素材。


## 2026-10-13 通用自动流程

默认入口现为新素材 → 原始参考 → 通用冻结区域与轨迹 → 实测完整预览 → 用户确认具体视频 → 同配方原生尺寸 JPG/XMP。新任务不运行旧联合求解或先导出全尺寸；旧任务及手动入口保留。四组区域按整段曝光质量和相对稳定性选择，也可在原始参考图上手动画框。实际中间调使用同一契约的参考区域，两个检查区域与求解区域不重叠。已有非线性创作曲线保留。

确认绑定任务、视频、完整帧清单、目标和有效配方；导出前重新核对实际图像、XMP 与来源。每帧原生尺寸来自 Adobe 脚本返回，并检查完整 JPEG 解码、色彩、配方及与预览的比例。输出在独立目录，原 RAW/XMP/ACR 不改；中断可复用已验证回执，不覆盖未知文件。跨工作目录共用 Adobe 任务锁。

验证：完整回归执行 385 项，唯一失败为测试中的 macOS /var 与 /private/var 路径等价断言；修正断言后相关 25 项复核通过。另有自动/手动区域、旧计划兼容、恒定光和变暗等模型检查。三条端到端离线测试实际使用 JPEG/XMP、区域与目标计算、实测求解、ffmpeg 编码以及原生尺寸交付验证，只替换 Adobe 显影器：包括无 XMP、准备/导出中断续跑，以及第 13 帧真实参数模型中 +1 EV 快门台阶的 24 帧序列。

隔离浏览器实际操作通过：恢复任务、自动区域叠加、载入并播放 MP4、未确认禁止导出、手动画框与坐标同步、区域变化撤销确认、刷新恢复、独立确认页、模拟全尺寸交付和原手动入口。修复视频与参考图展开时覆盖确认控件的布局问题；最终页面无脚本错误。

本轮没有调用真实 Adobe、改动用户素材或开始下一组实拍素材。以上证明实现和隔离工作流通过；跨素材的视觉泛化及新版 Adobe 原生尺寸回执仍需下一组真实素材验收。
